# 12-服务层抽象设计

> 状态：已实施（service 层、HTTP bridge、桌面托盘切换与 service 级编排测试均已完成）。
> 决策：抽 `internal/service` 用例层；桌面 WebView **保留 loopback HTTP**，托盘改为进程内调用 service；**不引入 Wails bindings**。

## 1. 背景与目标

当前 `internal/httpapi` 的 handler 里混着两类代码：

- **传输职责**（应留下）：JSON 解码、query/path 参数解析、HTTP 状态码与错误映射、SSE 流、静态 UI。
- **用例编排**（应抽走）：例如 `handlers_sync.go` 的 `syncRun`（edge 校验 → bisync 首次 resync 前置 → locator 解析 → `Jobs.Start`）、`handlers_remotes.go` 的 `remotesDelete`（remote 被存储节点引用时拒绝删除）、`handlers_rclone.go` 的版本选择/激活/删除与 `UseRcloneBinary` 联动。

桌面端目前有两条入口：WebView 走 loopback HTTP（与浏览器完全一致），托盘直接读写 `app.State`（`cmd/desktop/tray.go` 调 `Rclone.Status()`、`Mounts.List()` 等）。托盘想要“启动/停止 rclone”“查看挂载”之外的能力时，要么绕过编排直接戳 store（与 HTTP 行为不一致），要么自己发 HTTP（本机回环、无意义开销）。

目标分层：

```
cmd/ourboros / cmd/desktop            ← 组装（wire）与生命周期
        │
bridge 层  internal/httpapi           ← Web HTTP + SSE（唯一网络入口）
           cmd/desktop 托盘           ← 进程内直接调用
        │
service 层 internal/service           ← 用例：校验、编排、事务边界、事件发布
        │
domain 层  workspace / jobs / mounts / settings / rclone / events / persist / paths
        │
           rclone RC（127.0.0.1 HTTP JSON，现有 Client 不变）
```

收益：

1. HTTP 与桌面托盘对同一操作走**同一份用例代码**，行为（校验、冲突、副作用）天然一致。
2. 用例可以脱离 HTTP 做单测，编排规则（bisync resync 前置、remote 引用保护、idle 检查）不再只能靠 HTTP 级测试覆盖。
3. 未来若要加第三个入口（CLI 子命令、Wails bindings），只需再写一个薄 bridge。

## 2. 现状盘点（抽取对象）

`app.State`（`internal/app/state.go`）已经是 domain 容器：`Rclone *rclone.Supervisor`、`Workspace`、`Settings`、`Jobs`、`Mounts`、`Downloads`、`Events *events.Bus`。它保留为**组装根**，但不再被 bridge 直接消费。

各 handler 中需要下沉的编排逻辑：

| 位置 | 编排内容 | 去向 |
| --- | --- | --- |
| `handlers_sync.go` `syncRun` | edge 存在/kind/enabled 校验、bisync resync 前置、locator 解析、`Jobs.Start` | `service.SyncTasks.Run` |
| `handlers_sync.go` `syncTasksCreate/Patch` | `remotesIfReady`（rclone 未就绪时降级为 unknown）后写 workspace | `service.SyncTasks.Create/Patch` |
| `handlers_sync.go` `syncTasksDelete` | `ensureIdle`（job 运行中 / mount 活跃时 409） | `service.SyncTasks.Delete` |
| `handlers_workspace.go` 节点删除 | `remotesIfReady` 后调用 domain 的引用保护删除 | `service.Workspace.DeleteNode` |
| `handlers_remotes.go` `remotesList/Get` | `ListRemotes` + `config/dump` 聚合 type；`config/get` + providers 脱敏参数 | `service.Remotes.List/Get` |
| `handlers_remotes.go` `remotesDelete` | remote 名宽松校验 + workspace 引用检查（`remote_in_use`） | `service.Remotes.Delete` |
| `handlers_remotes.go` `remotesCreate/Update` | 严格命名规则、`nonInteractive/obscure` 固定参数 | `service.Remotes.Create/Update` |
| `handlers_files.go` `transfer` | 按 directory/move 选择 RC 命令与 payload，生成 impact 文案 | `service.Files.Copy/Move` |
| `handlers_files.go` `filesDownload` | locator 校验、`operations/stat` 确认非目录、`OpenServe` | `service.Files.OpenDownload`（流见 §5） |
| `handlers_rclone.go` `rcloneSelect/Activate/DeleteVersion` | `SafeVersion`、managed 路径推导、二进制存在性、删除后回退 system、`UseRcloneBinary` | `service.RcloneRuntime.*` |
| `handlers_rclone.go` `rcloneDownloadStart` | `Downloads.Start` + 进度回调桥接到 `Events.Publish` | `service.RcloneRuntime.DownloadStart` |
| `helpers.go` `remotesIfReady/ensureIdle` | 跨 store 的公共编排 | 移入 service 包内部 |

纯转发（`mountsList/mountStart/mountStop`、`settingsGet/Patch`、`jobs list/stop`、`systemInfo`、`/api/rc` 白名单代理）也一并收口到对应 service，保持 bridge 只依赖 service 一条规则，避免“有的走 service 有的戳 store”的双轨。

## 3. 包结构与依赖规则

新增一个包，按领域拆文件，不做子包：

```
internal/service/
    service.go      // Services 聚合 + New(state *app.State)
    system.go       // System
    rclone.go       // RcloneRuntime（含下载、版本管理）
    remotes.go      // Remotes
    files.go        // Files
    sync.go         // SyncTasks + Jobs 查询/停止
    mounts.go       // Mounts
    settings.go     // Settings
    workspace.go    // Workspace
    rc.go           // RCProxy（白名单 RC 代理）
```

依赖方向单向：

- `service` 可以 import `internal/app` 与全部 domain 包；**不得 import `net/http`**（`Files.OpenDownload` 返回的元数据用自定义结构，见 §5）。
- `httpapi` 只 import `service`、domain 的 **DTO 类型**与 `core`/`events`；不得再持有 `app.State`、不得直接调 store/supervisor。
- `app` 不 import `service`（由 `serve` 组装，无循环依赖）。
- DTO 直接复用 domain 现有类型（`jobs.Snapshot`、`mounts.Snapshot`、`workspace.Document`、`rclone.Status` 等），请求 body 结构体从 httpapi 移到 service 包；不引入平行 DTO 层，避免无谓拷贝。

组装（`internal/serve`）：

```go
state, err := app.New(ctx, appConfig(args))   // 不变
svcs := service.New(state)                    // 新增，唯一组装点
start(ctx, state, svcs, args.Host, args.Port, webDir)
```

`serve.Running` 调整为：

```go
type Running struct {
    URL      string
    Done     <-chan struct{}
    Services *service.Services   // 供桌面托盘进程内调用
    // State 不再导出；生命周期（Close）仍由 serve 内部持有 state 完成。
}
```

## 4. service 接口划分

方法签名以 `context.Context` 开头（进程内调用方传 `context.Background()` 或带超时的 ctx），错误一律返回 `*core.Error`（`InvalidRequest/NotFound/Conflict/Transport/NotRunning/IO`），HTTP 状态码映射仍由 `httpapi.writeError` 负责，**映射规则不变**。

```go
type Services struct {
    System        *System
    Rclone        *RcloneRuntime
    Remotes       *Remotes
    Files         *Files
    SyncTasks     *SyncTasks
    Mounts        *Mounts
    Settings      *Settings
    Workspace     *Workspace
    RC            *RCProxy
}
```

代表性签名（完整清单以实施为准，与 `router.go` 路由一一对应）：

```go
// SyncTasks
func (s *SyncTasks) List() ([]workspace.SyncTask, uint64)
func (s *SyncTasks) Create(ctx context.Context, body workspace.CreateSyncTask) (workspace.SyncTask, workspace.Document, error)
func (s *SyncTasks) Patch(ctx context.Context, id string, body workspace.PatchSyncTask) (workspace.SyncTask, workspace.Document, error)
func (s *SyncTasks) Delete(id string, revision uint64) (workspace.Document, error) // 内含 ensureIdle
func (s *SyncTasks) Run(ctx context.Context, id string, resync bool) (jobs.Snapshot, error)
func (s *SyncTasks) ListJobs() []jobs.Snapshot
func (s *SyncTasks) StopJob(jobID string) (jobs.Snapshot, error)

// Remotes
func (s *Remotes) List(ctx context.Context) ([]RemoteInfo, error) // name+type 聚合
func (s *Remotes) Get(ctx context.Context, name string) (RemoteDetail, error)
func (s *Remotes) Create(ctx context.Context, body RemoteBody) (string, error)
func (s *Remotes) Update(ctx context.Context, name string, body RemoteBody) error
func (s *Remotes) Delete(ctx context.Context, name string) error  // 引用检查

// RcloneRuntime
func (s *RcloneRuntime) Status() rclone.Status
func (s *RcloneRuntime) EnsureRunning(ctx context.Context) (rclone.Status, error)
func (s *RcloneRuntime) Stop(ctx context.Context) (rclone.Status, error)
func (s *RcloneRuntime) Select(selection RcloneSelection) (rclone.Status, error)
func (s *RcloneRuntime) DownloadStart(version string) (rclone.DownloadSnapshot, error) // 内部桥接 Events
func (s *RcloneRuntime) Activate(version string) (rclone.Status, error)
func (s *RcloneRuntime) DeleteVersion(version string) error
```

约定：

- **revision 乐观锁**：`revision` 是 service 的显式参数；`?revision=` 的解析与必填校验留在 bridge。
- **校验分工**：JSON 解码与 `revision` query 解析留 bridge；其余请求校验（必填字段、remote 命名规则、`SafeVersion`、locator 解析、状态前置）进 service，保证进程内调用与 HTTP 行为一致。
- **危险操作约束不变**：`impact`/`destructive`/`source`/`target` 文案仍由用例产出（从 handler 平移），前端确认流程零改动。
- **事件发布**：`events.Bus` 留在 domain；service 负责在用例内发布（下载进度回调从 handler 移入 `RcloneRuntime`）。事件名（`job/mount/download/settings`）是 API 契约，不改。

## 5. 两个特殊用例

**文件下载（流式）**：service 不做 HTTP 写出，返回流与元数据，bridge 负责头与拷贝：

```go
type DownloadStream struct {
    Name        string          // filepath.Base，供 Content-Disposition
    ContentType string
    Size        int64           // -1 表示未知
    Body        io.ReadCloser
}
func (s *Files) OpenDownload(ctx context.Context, q FileQuery) (*DownloadStream, error)
```

bridge 侧保持现有行为：`operations/stat` 的目录/不存在校验已进 service；`Content-Disposition`、`Content-Type`、`Content-Length`、`io.Copy` 留 handler。

**SSE**：订阅、keepalive（15s）、按事件名/下载 ID 过滤、`{type,data}` 信封格式全部留在 `httpapi/sse.go`，handler 改为从 `service` 拿 `*events.Bus`（`Services.Events()` 暴露只读订阅入口）。SSE 是传输职责，不下沉。

## 6. 桌面端变化

- WebView 继续加载 `http://127.0.0.1:<port>/?platform=...`，前端 **transport / SSE / 鉴权逻辑零改动**。
- 托盘从 `running.State` 切换到 `running.Services`：`Rclone.Status()/EnsureRunning/Stop`、`Mounts.List()` 改走 service；`watchSettings` 仍订阅 `events.Bus`。
- 进程内调用不经过 token/CORS——与现状一致（本机托盘可信），鉴权模型不变。
- `serve.Run` 的启动顺序、自动拉起 rclone、`scheduler.Run` 均不变；scheduler 是 domain 级消费者，继续直接用 `Workspace`/`Jobs`，不经过 service。

## 7. 方案取舍（已否决项）

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 桌面改 Wails bindings（IPC + Wails events 替代 SSE） | 否决 | 前端要维护第二套 transport 与事件通道，codegen 进构建链；与现有“无 Wails bindings”决策冲突，收益不足以抵消 |
| HTTP 与 bindings 双 bridge 并存 | 否决 | 长期维护两套通道；需要时再议，service 层不堵死这条路 |
| httpapi 继续直接持有 `app.State`，仅抽“复杂”用例 | 否决 | 双轨依赖会让编排散落回 handler，抽取失去意义 |
| 引入 Web 框架 | 否决 | 标准库 ServeMux 已够用，与本次目标无关 |

## 8. 迁移步骤

每步保持 `go test ./internal/... ./cmd/ourboros` 全绿；前端无改动，收尾跑一次 `cd frontend && npm run check` 回归。

1. **骨架**：建 `internal/service`，实现 `System/Settings/Mounts/Workspace/SyncTasks` 中纯转发方法；`httpapi.Handler` 改收 `*service.Services`，路由表（`router.go`）原样不动。
2. **重编排下沉**：`SyncTasks.Run/Delete`（含 `ensureIdle`）、`Remotes` 全部、`Files` 全部（含 `OpenDownload`）、`RcloneRuntime` 全部（含下载事件桥接、版本管理）。
3. **清理**：删除 httpapi 中已迁移的 helper（`remotesIfReady/ensureIdle` 等），确认 httpapi 不再 import `app`、不再触碰 store。
4. **桌面切换**：`Running` 结构调整为导出 `Services`；托盘改造。
5. **补测试**：为编排规则补 service 级单测——bisync 首跑必须 resync、disabled 任务 409、`remote_in_use`、运行中/挂载中删除冲突、删除受管版本后回退 system、rclone 未就绪时 sync task 创建降级。
6. **文档同步**：更新 `AGENTS.md`（Layout 增 `internal/service`，约束补“bridge 不得绕过 service 直触 store”）与 `docs/dev/02-架构设计.md`。

测试策略：现有 `internal/httpapi` 的 HTTP 级测试**不改断言、不改用例**，它们即行为回归网；新增测试只针对 service 编排。

## 9. 非目标

- 不改任何 API 路径、请求/响应结构、SSE 事件格式。
- 不改鉴权/CORS/Origin 模型，不改 RC 绑定与脱敏约束。
- 不拆改 domain store（workspace/jobs/mounts 等内部实现不动）。
- 不动前端代码与 Wails 窗口/托盘结构（仅托盘的服务访问方式变化）。

## 10. 验收标准

1. `httpapi` 无 `app.State` 依赖、无 domain store 直接调用；service 包无 `net/http` import。
2. 托盘与 HTTP 对同一操作产生一致行为（以 rclone start/stop、mount list 为抽查点）。
3. 全部既有 Go 测试原样通过；新增 service 单测覆盖 §8.5 列出的编排规则。
4. 前端 `npm run check` 通过且未改动；桌面 `wails3 dev` 手动冒烟（启动、托盘启停 rclone、挂载列表、退出清理）。
