# 04 - 核心功能模块

## 模块总览

| 模块 | 职责 | 首轮状态 |
|------|------|----------|
| rclone 管理 | 发现、下载、启动、attach、停止和版本管理 | 必须 |
| RC 适配层 | allowlist、超时、错误转换和敏感命令过滤 | 必须 |
| Workspace | 同步任务（节点/边持久化）、校验和 JSON 持久化 | 必须 |
| Remote/File | remote 配置、目录浏览和基础文件操作 | 必须 |
| Sync | 单向/双向同步、限速与限额参数、job、进度、取消和计划调度 | 必须 |
| Mount | 远程到本地的 mount 子进程生命周期 | 必须 |
| Settings | rclone 来源、配置路径、自动启动和 UI 偏好边界 | 必须 |
| 历史/多用户 | 任务历史、账号、权限和审计 | 后续 |

## rclone 管理

- 扫描并验证系统 PATH、自定义路径和托管版本。
- 选择优先级为用户指定路径 > 托管版本 > 系统 PATH。
- 托管版本支持查询、下载、校验、激活、删除和回滚。
- `RcloneSupervisor` 防止重复启动，检测异常退出并支持优雅停止。
- RC 只监听回环地址并使用临时凭据。

## RC 适配层

- 浏览器不直接连接 rclone RC。
- 常用操作由 typed API 映射到固定的 RC 命令和参数。
- 通用 `POST /api/rc/{command}` 只允许 allowlist 命令。
- command 只接受 `[A-Za-z0-9/_-]`，拒绝敏感配置导出命令。
- 统一超时、上游错误、未运行状态和响应转换。

## Workspace

- 画布功能已移除。workspace 文档仍以节点/边形式存储同步任务的端点与规则：
  - 端点节点只有 `local` / `remote` 两种，由任务 API 自动创建和复用，删除任务时清理不再被引用的节点。
  - 同步规则存放在 sync 边上，包含名称、操作、限速、限额、计划和最近结果。
  - 历史文档中的画布专用数据（action 节点、flow 边、视口）在加载时被清理。
- 校验节点引用、重复挂载、路径、remote 名称和挂载方向。
- 修改工作区后使用版本号防止并发覆盖，写入采用临时文件 + rename。

## Remote 与文件

- `config/listremotes` 返回 remote 列表。
- 支持 remote 创建和编辑，但敏感字段不进入 workspace JSON。
- `operations/list` 即时读取目录，不建立文件索引。
- 支持 mkdir、copy、move、delete、purge，并区分可逆/破坏性操作。
- `GET /api/files/download` 通过 loopback 代理 RC 文件服务器（`rcd --rc-serve`）流式下载单个文件：服务端先 `operations/stat` 确认目标是文件，再把上游字节透传给浏览器；RC 地址和凭据只在服务进程内部出现。
- 重命名复用 `operations/movefile`（目录用 `sync/move`），目标是同目录下的新名字。
- 前端浏览体验包含排序（目录置顶）、名称过滤、统一面包屑、上一级导航和文件/目录图标。
- 文件 API 统一校验 `fs`、`remote`、相对路径和操作类型。

## 同步任务与计划

- 同步任务 API 是顶层资源：创建时指定名称、源端点、目标端点、方向与操作、限速/限额和计划；端点节点在服务端自动复用或创建。
- 单向同步：`copy`（复制）、`move`（移动，源文件被删除）、`sync`（镜像，目标多余文件被删除）。
- 双向同步：`bisync`（rclone sync/bisync），变更（包括删除）向两个方向传播；首次运行必须 resync 建立基线，计划调度会跳过尚未 resync 的任务。
- 限速（`bw_limit`）：rclone 的带宽限制器是进程全局的，Ourboros 在任务运行期间通过 `core/bwlimit` 应用所有运行中限速任务的最小值，全部结束后恢复不限速。限速只对流式传输（本地↔云盘等）生效；本地↔本地等服务器端复制不产生流式数据，不受限速影响（与 rclone CLI 行为一致）。
- 单次大小上限（`max_transfer`）：rclone 自身的 MaxTransfer 检查对服务器端复制不生效，因此 Ourboros 轮询任务自身的统计字节，达到上限后主动 `job/stop` 中止本次任务（按搬运的总数据量计，含服务器端复制）；双向同步触发中止后可能需要 resync 恢复。
- 手动和计划执行使用任务上保存的同一套配置。
- `sync` 可能删除目标多余文件，`move` 会改变源内容，`bisync` 双向传播删除，运行前必须明确确认。
- 每条任务独立保存启用开关、预设频率或 cron、时区、下次运行和最近结果。
- 同一条任务不可并发运行；支持取消、失败、部分失败、过期和重试。
- 任务进度通过首次快照 + SSE 发送，断线重连后重新同步。

## 挂载生命周期

- 只允许 remote 源 → local 目标。
- 启动 `rclone mount` 子进程并记录 starting/mounted/stopping/stopped/failed 状态。
- 防止同一边重复挂载，停止时清理子进程和残留状态。
- 捕获退出码、stderr 和平台不支持错误。
- 默认服务重启不自动恢复 mount，除非以后增加明确设置。

## 应用设置

- rclone 来源、配置文件路径、自动启动偏好和工作区文件位置。
- 设置与 workspace JSON 都带 schema 版本并支持迁移。
- CLI 参数只覆盖当前进程，不隐式修改已保存配置。
- UI 主题、语言、面板宽度等非敏感偏好留在浏览器 localStorage。
