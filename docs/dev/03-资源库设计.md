# 03 - rclone 连接与存储端点设计

## 托管模式

`ourboros server` 启动后：

1. 在 `127.0.0.1` 选择空闲端口。
2. 为本次会话生成临时 RC 用户名和密码。
3. 执行 `rclone rcd --rc-addr 127.0.0.1:<port> --rc-user ... --rc-pass ...`。
4. 轮询 `core/version` 直到 ready。
5. 由 typed API 或受限 RC 适配层调用 rclone。

RC 地址、临时凭据只存在于服务端运行内存，既不返回浏览器也不写入设置文件。

## Attach 模式

`--rclone-url http://127.0.0.1:5572` 或 `RCLONE_RC_URL` 时不启动子进程，只连接已有 RC。

- Attach 会话不拥有外部 rclone 进程。
- `stop` 只清除 Ourboros 会话，不终止外部进程。
- 连接失败、版本查询失败或外部 RC 消失时，状态变为未就绪并保留可重连入口。

## rclone 来源

候选来源按以下顺序选择：

1. 用户指定的可执行文件路径。
2. Ourboros 应用数据目录中的托管版本。
3. 系统 PATH 中的 rclone。

每个候选必须通过 `rclone version` 验证。托管下载还必须校验官方 SHA-256 清单/签名。系统包管理器安装的 rclone 不由 Ourboros 覆盖更新。

## 存储节点

画布节点是存储端点，不是 Ourboros 实例：

```text
StorageNode {
  id: UUID,
  kind: "local" | "remote",
  label: String,
  position: { x: f64, y: f64 },
  local_path?: String,
  remote?: { name: String, path: String }
}
```

### 本地节点

- `local_path` 必须是规范化后的绝对路径。
- 服务端创建/更新时校验路径格式和访问权限。
- 不把本地文件列表写入数据库；浏览时即时调用文件 API。
- 默认可提供用户 HOME 作为本机入口，但不自动暴露任意系统目录。

### Remote 节点

- `remote.name` 必须来自 `config/listremotes`。
- `remote.path` 是 remote 内的相对路径，空路径表示 remote 根。
- 节点只保存 remote 引用和路径，不保存 provider 密钥、token 或完整配置。
- 默认流程选择已有 remote；新建/编辑 remote 通过受控配置 API 完成，成功后回填节点。

## 路径模型

rclone 操作统一拆分为 `fs` 和 `remote`：

| 节点类型 | `fs` | `remote` |
|----------|------|----------|
| 本地目录 | 本地路径或 HOME 下的规范化路径 | 相对路径，通常为空 |
| Remote | rclone remote 名称 | remote 内相对路径 |

服务端禁止路径穿越、隐式拼接未校验的 remote 名称和跨节点类型的非法路径转换。copy、move、sync、list、mkdir、delete、purge 都必须使用同一套路径校验器。

## 有向连线

连线从源节点指向目标节点。每条连线只允许一个关系类型：

- `sync`：源内容按保存的 `copy`、`move` 或 `sync` 策略写入目标。
- `mount`：仅允许 remote 源指向 local 目标，启动 `rclone mount` 到本地目录。

不支持远程 Ourboros 实例节点、双向隐含同步和远程到远程 mount。

## 持久化边界

- remote、凭证和文件真实数据：rclone 配置/存储。
- 工作区节点、连线、视口和计划：Ourboros 版本化 workspace JSON。
- 运行中的 job、RC 会话和 mount 进程：内存状态，必要时从 API 重新获取。
- 托管 rclone 版本：应用数据目录与版本元数据。
