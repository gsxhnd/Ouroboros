# 08 - 技术依赖

## Rust

| Crate/能力 | 用途 |
|------------|------|
| `axum` | HTTP API、SSE 和路由 |
| `tokio` | 异步运行时、任务和子进程 |
| `reqwest` | 调用 rclone RC |
| `serde` / `serde_json` | API、workspace 和设置 JSON |
| `uuid` | 节点、边、job 标识 |
| `chrono` 或等价时间库 | 时间戳、时区和计划状态 |
| `tower-http` | 静态文件、Origin/CORS 和 tracing layer |
| `clap` | CLI 与环境变量 |
| `tracing` | 日志和诊断 |
| `thiserror` | core 错误 |
| `anyhow` | binary 层错误聚合 |

下载校验、cron 解析和跨平台 mount 参数库在对应阶段选择，必须优先维护活跃、跨平台且不扩大安全边界的实现。

外部运行时是 rclone。支持系统 PATH、自定义路径和 Ourboros 下载的托管版本。

## 画布引擎决策门

正式添加画布依赖前，以同一 `CanvasAdapter` 接口验证下列方案：

| 方案 | 优势 | 成本/风险 | 默认判断 |
|------|------|-----------|----------|
| React Flow | React 集成、节点/边、缩放平移、minimap 和键盘能力成熟 | 新增依赖和样式适配 | 首选 |
| LiteGraph.js | 原生节点图能力强，接近 ComfyUI | React 状态、类型和样式整合成本高 | 备选 |
| Fabric.js | Canvas 绘制灵活 | 图编辑、连线和可访问性需自研 | 不作为首轮默认 |
| DOM + SVG | 依赖少、可完全控制 | 拖拽、命中测试、性能和无障碍全部自研 | 依赖受限时采用 |
| HTML5 Canvas 自研 | 大图性能潜力高 | 交互和可访问性成本最高 | 不采用 |

spike 验收：100 节点/200 边下拖拽和缩放可用；支持连线创建/删除、键盘删除、选中态、自定义节点/边、序列化/反序列化。若无新的许可或运行约束，选择 React Flow。
