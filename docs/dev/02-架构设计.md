# 02 - 架构设计

## 整体架构

```text
┌────────────────────────────────────────────────────────────┐
│ React Canvas Workspace                                     │
│ shadcn/ui + Zustand + i18next + TanStack Router            │
│ 只访问 Ourboros typed API，不直连 rclone RC                │
└───────────────────────────┬────────────────────────────────┘
                            │ 同源 HTTP / SSE
┌───────────────────────────▼────────────────────────────────┐
│ ourboros (Axum)                                             │
│ API 路由 + 参数校验 + 工作区/设置存储 + 事件流              │
│ rclone 管理 + 同步调度 + mount supervisor                   │
└───────────────┬───────────────────────────┬────────────────┘
                │ typed API / 受限 RC client │ 子进程
┌───────────────▼───────────────┐  ┌────────▼─────────────────┐
│ rclone rcd                    │  │ rclone mount             │
│ 回环地址 + 临时凭据           │  │ 受监管的挂载进程          │
└──────────────────────────────┘  └──────────────────────────┘
```

Rust/Axum 是唯一可信控制面。React 不知道 RC 地址和凭据，也不直接执行系统命令。所有路径、remote 名称、同步方向、危险操作和状态转换都由服务端校验。

## 进程与模块

```text
ourboros
├── CLI / server
├── HTTP router
├── application state
│   ├── RcloneSupervisor
│   ├── WorkspaceStore
│   ├── SyncScheduler / JobStore
│   └── MountSupervisor
├── domain
│   ├── workspace
│   ├── remotes / files
│   ├── sync
│   ├── mounts
│   └── settings
└── static web handler
```

`ourboros-core` 提供 rclone RC 客户端、进程监管、错误类型和可复用的底层服务；`ourboros` 提供 HTTP、CLI、持久化和应用编排。前端业务类型必须与 API 契约对应，不在组件内拼装 RC 请求。

## 单一二进制与运行模式

| 子命令 | 用途 |
|--------|------|
| `ourboros server` | HTTP 服务、Web 静态资源、rclone 和业务任务 |
| `ourboros version` | 打印版本 |

`server` 支持两种 rclone 会话：

- 托管模式：Ourboros 选择可执行文件、生成临时 RC 凭据、启动 `rclone rcd` 并监管子进程。
- Attach 模式：连接用户已启动的 RC；Ourboros 不拥有外部进程，stop 只断开会话。

## 请求与事件流

1. 浏览器读取 `/api/workspace` 和系统状态。
2. 用户通过画布创建或修改节点/连线，Axum 校验后原子写入 workspace JSON。
3. 手动同步或计划调度创建 job；任务调用受限 rclone RC 操作。
4. Rust 通过 SSE 发送任务/挂载状态；浏览器断线后先拉取快照，再指数退避重连。
5. mount 由 Rust 启动并监管独立子进程，状态与退出原因通过 API/SSE 暴露。

## 信任边界

- 浏览器只访问 Ourboros 同源 `/api`。
- RC 只监听 `127.0.0.1`，使用启动时生成的临时凭据。
- RC URL、RC 凭据、remote token 和 `config/dump` 不通过 API 返回，也不落盘。
- `POST /api/rc/{command}` 仅允许明确 allowlist 命令；业务操作优先使用 typed API。
- Ourboros 默认只绑定 `127.0.0.1`。支持局域网访问前必须增加 HTTP 鉴权、Origin/CSRF 防护和 TLS 部署说明。

## Web UI 托管

前端构建产物 `web/dist` 不 embed 进二进制，查找顺序为：

1. CLI `--webui` / `--web-dir`
2. `OURBOROS_WEB_DIR`
3. 可执行文件旁的 `web/`

显式指定的目录必须包含 `index.html`，否则拒绝启动。未指定且找不到 UI 时仍启动 API-only 服务。开发使用 Vite `:1420` 代理到后端 `127.0.0.1:8080`。

## Monorepo 目标结构

```text
Ourboros/
├── crates/
│   ├── ourboros-core/     # rclone、任务和进程底层能力
│   └── ourboros/          # CLI、Axum、存储和应用编排
├── web/                   # React Canvas UI
└── docs/dev/              # 产品、接口和实施文档
```
