# 11 - Web 服务打包和发布指南

发布目标是 **Ourboros Web 服务 + React 静态资源**，不是 Tauri/WebView 桌面应用。

## 构建

```bash
# 前端
cd web
npm ci
npm run typecheck
npm run lint
npm run build
cd ..

# Rust
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build -p ourboros --release
```

构建结果：

- Rust：`target/release/ourboros`，Windows 为 `ourboros.exe`。
- Web：`web/dist`。

## 发布包结构

```text
Ourboros/
├── ourboros
└── web/
    ├── index.html
    └── assets/
```

启动命令：

```bash
./ourboros server --web-dir ./web
```

应用默认监听 `127.0.0.1:8080`，由用户使用系统浏览器访问，不创建桌面 WebView。找不到 `index.html` 时仍可作为 API-only 服务启动。

## rclone 依赖

发布包不捆绑 rclone。运行时按以下来源选择：

1. 用户指定路径。
2. Ourboros 应用数据目录中的托管版本。
3. 系统 PATH。

找不到 rclone 时服务仍启动，WebUI 提供重新扫描、选择路径和下载托管版本的入口。托管版本在运行时下载到应用数据目录，校验官方签名/ SHA-256 清单后激活，不覆盖系统包管理器安装的版本。

## CI 发布要求

发布 workflow 必须：

1. 安装 Node.js、Rust 和目标平台 target。
2. 使用 lockfile 构建、typecheck、lint 和测试 React。
3. 为目标平台构建 Rust。
4. 将同一份 `web/dist` 与对应 Rust 二进制组合成发布包。
5. 生成 SHA-256 checksums。
6. 在 tag 构建中上传各平台 artifact 并创建 release。

当前 workflow 中不得引用 Cargo 不存在的 `app` feature；发布前必须验证 workflow 与 workspace manifest 一致。

## 平台产物

首轮支持：

- `x86_64-pc-windows-msvc`
- `aarch64-pc-windows-msvc`
- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`
- `x86_64-apple-darwin`
- `aarch64-apple-darwin`

首版使用 zip 或 tar.gz。安装器、AppImage、DEB、MSI 和 macOS `.app` 后置评估；不得依赖仓库中不存在的旧打包脚本。

## 发布前验收

- 无 rclone 时 API 和首页能启动并显示未就绪状态。
- 本地节点、remote 节点、同步边和 mount API 在发布包中可用。
- `web/dist` 由发布包正确托管，刷新任意前端路由不会丢失入口。
- RC URL/凭据、remote token 和敏感日志在生产构建中不泄露。
- Rust 与 Web 检查命令在干净环境通过。

## 桌面端

Tauri 不属于当前发布范围。未来实现时复用 React 与 `ourboros-core`，优先复用现有 HTTP 控制面；另行补充 capabilities、sidecar/托管下载、托盘、更新、签名和跨平台 CI。
