# 11 - Web 服务打包和发布指南

发布目标是 **Ourboros Web 服务 + React 静态资源**。桌面端是可选的 Wails 窗口，不进入 Docker / K8s 镜像。

## 构建

```bash
# 前端
cd web
npm ci
npm run typecheck
npm run lint
npm run build
cd ..

# Go 服务
gofmt -w cmd internal
go test ./internal/... ./cmd/ourboros
CGO_ENABLED=0 go build -o ourboros ./cmd/ourboros

# 桌面窗口（需要本机 WebView 工具链）
go build -o Ourboros ./cmd/desktop
```

构建结果：

- 服务：`ourboros`，Windows 为 `ourboros.exe`。
- 桌面：`Ourboros`。
- Web：`web/dist`。

## 发布包结构

```text
Ourboros/
├── ourboros
└── web/
    ├── index.html
    └── assets/
```

启动命令：

```bash
./ourboros server --webui ./web
```

应用默认监听 `127.0.0.1:8080`。服务可以只给浏览器使用；`cmd/desktop` 用 Wails 打开同一个地址。显式传入 `--webui` / `--web-dir` 但找不到 `index.html` 时拒绝启动；未指定 UI 目录时可作为 API-only 服务启动。

## rclone 依赖

发布包不捆绑 rclone。运行时按以下来源选择：

1. 用户指定路径。
2. Ourboros 应用数据目录中的托管版本。
3. 系统 PATH。

找不到 rclone 时服务仍启动，WebUI 提供重新扫描、选择路径和下载托管版本的入口。托管版本在运行时下载到应用数据目录，校验官方签名/ SHA-256 清单后激活，不覆盖系统包管理器安装的版本。

## CI 发布要求

发布 workflow 必须：

1. 安装 Node.js 和 Go 1.26。
2. 使用 lockfile 构建、typecheck、lint 和测试 React。
3. 用 `CGO_ENABLED=0` 为目标平台构建 `cmd/ourboros`。
4. 将同一份 `web/dist` 与对应服务二进制组合成发布包。
5. 生成 SHA-256 checksums。
6. 在 tag 构建中上传各平台 artifact 并创建 release。

桌面包需要在对应操作系统上用 CGO 构建 `cmd/desktop`，不放进无界面的服务镜像。

## 平台产物

首轮支持：

- `windows/amd64`
- `windows/arm64`
- `linux/amd64`
- `linux/arm64`
- `darwin/amd64`
- `darwin/arm64`

首版使用 zip 或 tar.gz。安装器、AppImage、DEB、MSI 和 macOS `.app` 后置评估；不得依赖仓库中不存在的旧打包脚本。

## 发布前验收

- 无 rclone 时 API 和首页能启动并显示未就绪状态。
- 本地节点、remote 节点、同步边和 mount API 在发布包中可用。
- `web/dist` 由发布包正确托管，刷新任意前端路由不会丢失入口。
- RC URL/凭据、remote token 和敏感日志在生产构建中不泄露。
- Go 与 Web 检查命令在干净环境通过。

## 桌面端

`cmd/desktop` 复用 React 与 HTTP 控制面。托盘、自动更新、签名和跨平台桌面 CI 仍后置。
