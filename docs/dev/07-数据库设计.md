# 07 - 配置与状态持久化

## 总原则

Ourboros 不维护文件索引、remote 凭据或素材库业务数据库。首轮使用版本化 JSON 和运行时内存状态；以后若引入任务历史/用户账号，再单独评估 SQLite 等数据库。

## 数据归属

| 数据 | 权威来源 | 持久化位置 |
|------|----------|------------|
| remotes / 凭证 | rclone | `rclone.conf` 或 `--rclone-config` |
| 文件和目录 | rclone/本地文件系统 | 原始存储，不复制索引 |
| workspace 节点、边、视口、计划 | Ourboros | 应用数据目录 `workspace.json` |
| rclone 来源、配置路径、自动启动 | Ourboros | 版本化设置 JSON |
| 托管 rclone 版本 | Ourboros | 应用数据目录 + 版本元数据 |
| 运行中的 RC 会话 | Ourboros | 仅内存 |
| job 和 mount 进程状态 | Ourboros/rclone | 仅内存，重启后重新获取 |
| 主题、语言、面板宽度 | 浏览器 | localStorage |

## Workspace 文档

```text
WorkspaceDocument {
  schema_version: u32,
  revision: u64,
  nodes: Vec<StorageNode>,
  edges: Vec<ConnectionEdge>,
  viewport: Viewport,
  updated_at: DateTime
}
```

节点包含 local 绝对路径或 remote 名称/相对路径。边包含 source、target、关系类型以及 sync/mount 配置。workspace JSON 不包含 remote 凭据、RC URL、临时凭据、文件列表和 job 历史。

## 设置文档

设置包含：

- schema 版本。
- rclone 来源选择、配置文件路径和自动启动。
- workspace 文件位置。
- 未来可选的 mount 自动恢复开关。

CLI 参数只覆盖当前进程解析结果，除非通过设置 API 明确保存，不隐式修改文件。

## 写入与迁移

- 所有 JSON 文件写入同目录临时文件后 `rename` 原子替换。
- 每个文档必须包含 `schema_version`，读取时执行显式迁移。
- 迁移失败时保留原文件、返回可诊断错误，不覆盖有效数据。
- workspace 写操作携带 `revision`，服务端拒绝过期更新并返回 `409`。
- 删除节点/边前先停止关联 mount 或拒绝带运行状态的删除。

## 生命周期

- 服务首次启动创建空 workspace 和默认 viewport。
- 服务重启恢复节点、边、计划配置和位置。
- 计划调度器根据保存的配置重建任务，但不重复执行历史 job。
- mount 默认不自动恢复；启动后状态显示为 stopped，用户手动挂载。
- rclone 缺失时 workspace 仍可读取和编辑，依赖 rclone 的操作返回明确未就绪状态。

## 安全边界

- 不把 remote token、RC 临时凭据、完整 `config/dump` 或敏感 mount 参数写入 JSON。
- workspace 路径写入前规范化并校验；不允许路径穿越和未经授权的系统目录。
- 日志不打印凭据、完整 RC 请求 body 或 remote secret。
