# 07 - 配置与状态持久化

## 总原则

Ourboros 不维护文件索引、remote 凭据或素材库业务数据库。配置使用版本化 JSON，运行时状态保存在内存；同步执行历史使用嵌入式 KV 存储 bbolt（`go.etcd.io/bbolt`），不引入外部数据库服务。

## 数据归属

| 数据 | 权威来源 | 持久化位置 |
|------|----------|------------|
| remotes / 凭证 | rclone | `rclone.conf` 或 `--rclone-config` |
| 文件和目录 | rclone/本地文件系统 | 原始存储，不复制索引 |
| workspace 节点、边、视口、计划 | Ourboros | 应用数据目录 `workspace.json` |
| rclone 来源、配置路径、自动启动 | Ourboros | 版本化设置 JSON |
| 托管 rclone 版本 | Ourboros | 应用数据目录 + 版本元数据 |
| 同步执行历史 | Ourboros | bbolt 文件 `<数据目录>/ourboros.db`（`--history-db` / `OURBOROS_HISTORY_DB` 可覆盖） |
| 进程日志 | Ourboros | `<数据目录>/log/ourboros.log`（`--log-dir` / `OURBOROS_LOG_DIR` 可覆盖） |
| 运行中的 RC 会话 | Ourboros | 仅内存 |
| job 和 mount 进程状态 | Ourboros/rclone | 仅内存，重启后重新获取 |
| 主题、语言、面板宽度 | 浏览器 | localStorage |

## Workspace 文档

```text
WorkspaceDocument {
  schema_version: u32,
  revision: u64,
  nodes: Vec<StorageNode>,
  edges: Vec<ConnectionEdge>,
  updated_at: DateTime
}
```

节点包含 local 绝对路径或 remote 名称/相对路径。边包含 source、target、关系类型以及 sync/mount 配置。workspace JSON 不包含 remote 凭据、RC URL、临时凭据、文件列表和 job 历史。

## 执行历史（bbolt）

`internal/history` 用 bbolt 保存每个同步任务的每次执行记录：

- 存储文件默认是 `<数据目录>/ourboros.db`，与 workspace.json、settings.json 同住一个数据目录（备份/挂载卷只需一份），父目录不存在时自动创建；`--history-db` / `OURBOROS_HISTORY_DB` 可覆盖。
- 单一 `runs` 桶，key 为 `<task_id>/<20 位纳秒时间戳>/<run_id>`：定宽时间戳让字节序即时间序，按任务前缀扫描天然有序，倒序即"最新在前"，无需二级索引。
- 记录包含任务 ID、操作、源/目标、触发来源（manual/scheduled）、状态、起止时间、错误与最终统计（字节数、文件数、检查数、错误数、速度）。
- 每任务最多保留 100 条，超出淘汰最旧记录。
- 启动时把上个进程遗留的 `running` 记录修复为 `interrupted`（真实结局不可知）。
- 写入点：`jobs.Store` 启动回调（状态 running）与终态回调（含立即失败的启动，例如 rclone 未就绪）。任务删除时同步清除其全部记录。
- 历史是增强功能：数据库打不开（如目录不可写）时降级为无历史，服务照常启动；相关 API 返回空列表。

## 进程日志

`internal/logs` 在服务与桌面启动时初始化：

- 日志默认写到 `<数据目录>/log/ourboros.log`（目录不存在时自动创建，`--log-dir` / `OURBOROS_LOG_DIR` 可覆盖）。
- 输出同时保留 stderr：`task dev`、Docker 等场景依旧实时可见；文件供长期排查。
- 单个日志文件超过 20MB 时，下次启动轮转为 `ourboros.log.old`，只保留一代，避免无限增长。
- 目录打不开（例如桌面应用工作目录不可写）时降级为仅 stderr，不影响服务启动。

## 设置文档

设置包含：

- schema 版本。
- rclone 来源选择、配置文件路径和自动启动。
- workspace 文件位置。
- 未来可选的 mount 自动恢复开关。

CLI 参数只覆盖当前进程解析结果，除非通过设置 API 明确保存，不隐式修改文件。

## 写入与迁移

- 所有 JSON 文件写入同目录临时文件后 `rename` 原子替换。
- 每个文档必须包含 `schema_version`，读取时执行显式迁移。
- 迁移失败时保留原文件、返回可诊断错误，不覆盖有效数据。
- workspace 写操作携带 `revision`，服务端拒绝过期更新并返回 `409`。
- 删除节点/边前先停止关联 mount 或拒绝带运行状态的删除。

## 生命周期

- 服务首次启动创建空 workspace。
- 服务重启恢复节点、边和计划配置。
- 计划调度器根据保存的配置重建任务，但不重复执行历史 job。
- mount 默认不自动恢复；启动后状态显示为 stopped，用户手动挂载。
- rclone 缺失时 workspace 仍可读取和编辑，依赖 rclone 的操作返回明确未就绪状态。

## 安全边界

- 不把 remote token、RC 临时凭据、完整 `config/dump` 或敏感 mount 参数写入 JSON。
- workspace 路径写入前规范化并校验；不允许路径穿越和未经授权的系统目录。
- 日志不打印凭据、完整 RC 请求 body 或 remote secret。
