# 10 - 设计决策与注意事项

## 已确认决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 产品 | 画布优先的 rclone Web UI | 用可视化工作区统一配置同步和挂载 |
| 节点 | 本地目录或 rclone remote/path | 与 rclone 数据源直接对应 |
| 连线 | 有向配对 | 明确源和目标，便于同步与安全确认 |
| 关系 | 每条线一种类型：sync 或 mount | 降低状态歧义，面板行为可预测 |
| 同步策略 | 建线时保存 copy/move/sync | 手动和计划执行保持一致 |
| 计划 | 每条 sync 线独立，预设 + cron | 兼顾普通用户和高级周期 |
| 挂载 | 仅 remote → local，真实进程生命周期 | 符合 rclone mount 的本地挂载语义 |
| 工作区 | 单一默认画布 | 首轮聚焦核心工作流，避免多图迁移复杂度 |
| 持久化 | 服务端版本化 JSON + 原子写入 | 可跨浏览器恢复且不引入业务数据库 |
| rclone | 托管 rclone rcd + 受限 RC 代理 | 不重新实现云存储协议且隔离高权限 RC |
| 前后端通信 | React 只访问 typed API | 浏览器不接触 RC 地址、凭据和 token |
| 桌面形态 | Wails 窗口 + 同一个 HTTP 服务 | 本机、浏览器和服务器使用同一控制面 |

## 待决策事项

### 画布引擎

Phase 0 通过统一 `CanvasAdapter` 对 React Flow、LiteGraph.js、DOM + SVG 做 spike。默认选择 React Flow；若依赖、许可或性能约束不满足，再选择备选方案。业务模型不得直接绑定画布库 API。

### 平台挂载参数

macOS、Linux、Windows 的 mount 参数和系统权限不同。首轮只开放经过平台验证的选项，未经验证的参数不能由前端自由透传。

### 自动恢复挂载

默认关闭。开启前必须补充：启动权限、开机启动语义、残留进程识别、挂载点清理和失败恢复。

## 不可违反的规则

1. RC 永远不监听公网或局域网地址；Ourboros 默认只监听 `127.0.0.1`。
2. WebUI 不持有或持久化 RC 凭据、remote token、完整 `config/dump`。
3. typed API 必须校验 remote 名称、相对路径、绝对本地路径、操作类型和边方向。
4. `sync`、`move`、delete、purge 和 mount 等危险操作必须明确展示源、目标和影响。
5. workspace 和设置 JSON 必须带 schema 版本并原子写入。
6. rclone 缺失时服务仍应启动，依赖 rclone 的操作返回可诊断的未就绪状态。
7. 不覆盖由 Homebrew、apt、winget 等系统包管理器安装的 rclone。
8. 支持 `0.0.0.0`、NAS 或多用户访问前，必须先实现 HTTP 鉴权、CSRF/Origin 防护和 TLS。

## 风险与处理

| 风险 | 处理 |
|------|------|
| `sync` 删除目标多余文件 | 服务端保留操作策略，UI 二次确认并展示源/目标 |
| rclone/网络中断 | job 状态、重连、部分失败和可重试错误明确区分 |
| workspace 并发覆盖 | revision 乐观并发控制，冲突返回 `409` |
| mount 子进程残留 | supervisor 记录 PID/退出码，停止和异常路径统一清理 |
| download 经由 RC 文件服务器 | `--rc-serve` 仅在 loopback rcd 上开启，且 rcd 始终启用 RC 认证；typed API 只暴露 `/api/files/download`，URL 与凭据不出服务进程，下载前先 stat 拒绝目录和不存在文件 |
| remote 凭据泄露 | 不开放 `config/dump`，日志和响应脱敏 |
| 画布性能退化 | 适配层 spike、memo、批量保存和长列表虚拟化 |
