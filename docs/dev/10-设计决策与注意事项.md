# 10 - 设计决策与注意事项

## 已确认决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 产品 | 同步任务页为首页的 rclone Web UI | 画布方向已移除，任务列表形式更直接 |
| 同步任务 | 任务 = 名称 + 源/目标端点 + 方向/操作 + 参数 | 与 rclone 数据源直接对应，配置即任务 |
| 端点 | 本地目录或 remote/path，存储为 workspace 节点 | 复用既有校验和持久化，节点自动复用与清理 |
| 单向同步 | `copy` / `move` / `sync` | 手动和计划执行保持一致 |
| 双向同步 | rclone `sync/bisync`，首次运行 resync | 复用 rclone 能力；resync 语义必须显式确认 |
| 限速 | `core/bwlimit` 进程全局应用运行中任务的最小值 | rclone 限制器不支持按调用生效；取最小值保证都不超 |
| 单次大小上限 | RC `_config` MaxTransfer + CutoffMode=HARD | 按调用生效且按任务自身传输量计算 |
| 挂载 | 仅 remote → local，真实进程生命周期 | 符合 rclone mount 的本地挂载语义 |
| 持久化 | 服务端版本化 JSON + 原子写入 | 可跨浏览器恢复且不引入业务数据库 |
| 访问控制 | 回环免鉴权；非回环绑定（Docker/NAS）必须 `--auth-token` | Docker 端口映射需要绑 0.0.0.0，最小 Bearer token + Origin 校验兜底；TLS 留待对外发布 |
| rclone | 托管 rclone rcd + 受限 RC 代理 | 不重新实现云存储协议且隔离高权限 RC |
| 前后端通信 | React 只访问 typed API | 浏览器不接触 RC 地址、凭据和 token |
| 桌面形态 | Wails 窗口 + 同一个 HTTP 服务 | 本机、浏览器和服务器使用同一控制面 |
| 桌面壳适配 | 侧边栏贯穿全高、可拖宽（ui/resizable）可折叠，mac 由其顶部 28px 拖拽空条承载红绿灯；服务状态与设置入口钉在侧边栏底部；主窗口大小 / 位置写 window-state.json 跨启动恢复；`?platform=` 首次读到即落 localStorage | 红绿灯固定居中在 28px 系统标题栏、Wails 无法移动——空条同高即视觉居中；客户端导航会丢查询参数，GUI 内刷新需存储兜底 |

## 待决策事项

### 平台挂载参数

macOS、Linux、Windows 的 mount 参数和系统权限不同。首轮只开放经过平台验证的选项，未经验证的参数不能由前端自由透传。

### 自动恢复挂载

默认关闭。开启前必须补充：启动权限、开机启动语义、残留进程识别、挂载点清理和失败恢复。

## 不可违反的规则

1. RC 永远不监听公网或局域网地址；Ourboros 默认只监听 `127.0.0.1`。
2. WebUI 不持有或持久化 RC 凭据、remote token、完整 `config/dump`。
3. typed API 必须校验 remote 名称、相对路径、绝对本地路径、操作类型和同步/挂载端点。
4. `sync`、`move`、`bisync`、delete、purge 和 mount 等危险操作必须明确展示源、目标和影响；双向同步首次运行必须确认 resync。
5. workspace 和设置 JSON 必须带 schema 版本并原子写入。
6. rclone 缺失时服务仍应启动，依赖 rclone 的操作返回可诊断的未就绪状态。
7. 不覆盖由 Homebrew、apt、winget 等系统包管理器安装的 rclone。
8. 支持局域网 / Docker / NAS 访问前必须有访问控制。当前已实现最小 token 鉴权：`--auth-token`（env `OURBOROS_TOKEN`）配置后，非回环绑定才被允许，所有 `/api` 请求必须携带 `Authorization: Bearer`（SSE 用 `access_token` 查询参数），跨源 `Origin` 被拒绝。这仅覆盖开发与可信内网场景，对外发布仍需 TLS 与完整 Origin/CSRF 防护。

## 风险与处理

| 风险 | 处理 |
|------|------|
| `sync` 删除目标多余文件 | 服务端保留操作策略，UI 二次确认并展示源/目标 |
| `bisync` 双向传播删除 | 首次运行 resync 显式确认；出错后提供独立的重新初始化操作 |
| 限速是进程全局的 | 多任务并发时应用最小限速，全部结束恢复不限速；UI 明示语义 |
| MaxTransfer 中止中断 bisync | job 报错可见，用户通过 resync 恢复 |
| rclone/网络中断 | job 状态、重连、部分失败和可重试错误明确区分 |
| workspace 并发覆盖 | revision 乐观并发控制，冲突返回 `409` |
| mount 子进程残留 | supervisor 记录 PID/退出码，停止和异常路径统一清理 |
| download 经由 RC 文件服务器 | `--rc-serve` 仅在 loopback rcd 上开启，且 rcd 始终启用 RC 认证；typed API 只暴露 `/api/files/download`，URL 与凭据不出服务进程，下载前先 stat 拒绝目录和不存在文件 |
| remote 凭据泄露 | 不开放 `config/dump`，日志和响应脱敏 |
